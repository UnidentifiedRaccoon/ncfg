# Диагностика ресурсов сайта и Вебвизора

## Что подготовлено

- Страница статьи отличает успешный пустой ответ CMS от ошибки запроса. Ошибка проходит в error boundary с повторной попыткой; metadata и содержимое используют один результат в рамках HTTP-запроса через React cache.
- В мобильной форме поля идут сразу после вступления. Ошибка валидации получает фокус; повторное нажатие с той же ошибкой также возвращает к ней. Следующий Tab ведёт к первому полю.
- Production-сборка наследует каталог .next/static из активной ревизии ncfg-web по digest. CSS, JS, шрифты и изображения, лежащие в этом каталоге, сохраняются в новых образах.
- При замене файла начинается окно хранения 21 день. Последующие сборки сохраняют исходный срок, а возвращённый в текущую сборку файл снова становится текущим. Manifest хранится вне публичного каталога.
- Сборка блокируется при ошибке получения предыдущих файлов или повреждённом архиве. CI последовательно выполняет релизы и отклоняет web-образ старше пяти дней, оставляя запас сверх 15 дней хранения записей Вебвизора. Временная метка обновляет слой архива даже при повторном использовании кеша сборки.

Этот механизм действует в подготовленном production pipeline. Первое включение подхватит файлы активного образа; уже утраченные файлы более ранних образов он не восстанавливает. Прямой rollback на старый образ не способен добавить в него ресурсы будущих сборок: для сохранения архива выпускайте прежнюю версию кода новой сборкой. Медиа Strapi и файлы public со стабильными именами требуют отдельной политики хранения и версионирования; содержимое одного URL нельзя одновременно заменить и сохранить историческим.

## Диагностика в Метрике

После публикации клиентская instrumentation отправляет через метод params поле site_resource_error с двумя значениями:

| Поле | Значения |
|---|---|
| kind | css, script, image или font |
| release | Git SHA сборки либо unknown |

На один документ отправляется не более одного события каждого типа. URL ресурсов, query-параметры, содержимое форм, сообщения исключений и контакты не передаются этим кодом. Это индикаторы наличия ошибки, а не счётчик всех неудачных запросов.

Диагностика работает только в production, при настроенном счётчике, на основном origin сайта и вне iframe. Локальные страницы, preview без счётчика, эксперименты, Storybook и плеер Метрики исключены. Новые цели в Метрике не нужны.

Слушатель ошибок ресурсов ставится до hydration. После load дополнительно проверяются отсутствующие активные CSS и изображения с завершённой неудачной загрузкой; проверяются ошибки FontFaceSet. Это покрывает часть ошибок, случившихся до подключения слушателя.

В отчётах «Параметры событий» и «Параметры визитов» можно искать site_resource_error, затем сопоставлять kind и release с визитами. Отсутствие параметра не доказывает отсутствие сбоя: при блокировке Метрики или невозможности запуска JavaScript сигнал может не дойти. Ошибка отдельного ресурса также не доказывает, что вся страница была непригодна.

## HTTP-проверка без авторизации

Из корня проекта:

    node scripts/check-webvisor-assets.mjs https://ncfg.ru /_next/static/chunks/ACTUAL_HASH.css

Подставьте точный CSS из реальной страницы или записи. Можно передать несколько путей. Команда выполняет только GET к origin и публичному прокси Вебвизора. JSON выводит их раздельные HTTP-статусы, Content-Type, размер, SHA-256 и совпадение содержимого. isCssResponse означает успешный непустой ответ с MIME text/css; синтаксис CSS эта проверка не разбирает.

status: null означает, что HTTP-ответ не получен. Ошибка прокси не переносится на реальный визит. Прямой запрос к прокси без сессии не заменяет сетевой журнал самого браузера. Команда не отправляет заявки, не читает cookies и не меняет настройки.

После выпуска проверяйте CSS нового документа и CSS предыдущей активной версии. Затем выполните контрольный визит с известным временем и сравните его реальное оформление с записью. Старые URL, вышедшие за окно хранения, не должны бессрочно оставаться обязательной проверкой релиза.

## Проверки изменений

    node --test scripts/retain-next-static.test.mjs scripts/check-webvisor-assets.test.mjs
    cd apps/web
    ./node_modules/.bin/tsc --noEmit --incremental false
    node --import tsx --test shared/lib/news.test.ts shared/lib/resource-diagnostics.test.ts

Перед production нужно выполнить сборку образа и проверку наследования ресурсов в CI. Локальные тесты алгоритма не заменяют проверку Docker/Registry и разрешений CI на чтение активной ревизии. Подготовленные изменения не запускают production автоматически из рабочей папки.
