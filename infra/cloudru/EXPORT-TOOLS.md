# Инструменты экспорта и проверки восстановления

Исторический комплект переноса НЦФГ из Yandex Cloud в октябре 2026 года.
Это не текущая система ежедневных бэкапов Cloud.ru и не команда запуска сайта.
Идентификаторы ресурсов, адреса и production digest в исходниках относятся к той
миграции; перед новым экспортом их нужно отдельно сверить с согласованным источником.

## Состав и зависимости

Все семь файлов используют только стандартную библиотеку Python; pip-зависимостей нет.
Минимальная версия по используемым API — Python 3.9. Проверено на Python 3.14.6/macOS.

| Файл | Вход и результат | Дополнительные зависимости и эффекты |
| --- | --- | --- |
| [export-images.py](export-images.py) | JSON-массив инвентаризации Registry с name, digest, tags; создаёт OCI layout, index.json и export-report.json. По умолчанию два закреплённых production digest; `--all-images` расширяет выборку внутри двух разрешённых репозиториев. | `yc` в PATH, профиль default, доступ чтения Registry; получает IAM-токен в память, скачивает образы. Нужен свободный объём под недостающие blobs плюс 8 GiB. Docker не нужен. |
| [export-media.py](export-media.py) | Каталог назначения; создаёт objects/ и manifest.json с размерами, метаданными и SHA-256. | HTTPS-доступ к старому публичному бакету Yandex, включая ListObjectsV2. Проверяет стабильность списка до/после, ETag и размеры. Не использует ключи. |
| [export-pages.py](export-pages.py) | Каталог назначения; сохраняет главную, sitemap, robots и разрешённые страницы sitemap, пишет manifest.json. | `yc`, профиль default, право вызова старого приватного web-контейнера. Только GET. Это снимок страниц, а не резервная копия БД. Неполный экспорт завершается с кодом 1 и сохраняет отчёт. |
| [export-postgres.py](export-postgres.py) | ID отдельного recovery-кластера и путь dump; создаёт custom dump, .sha256, .json, source-row-counts.json, row-counts.sql и публичный CA. | `yc`, чтение метаданных кластера и согласованного Lockbox payload; pg_dump, pg_restore, psql версии 16; сеть до recovery-клона или заранее проверенный SSH-туннель. |
| [verify-export.py](verify-export.py) | Корень экспорта с media/ и images/; проверяет локальные байты и граф OCI, выводит JSON. | Только чтение локальных файлов, без сети и Docker. |
| [verify-postgres.py](verify-postgres.py) | Доверенный dump и сопроводительные файлы; создаёт restore-verification.json. | postgres, initdb, psql, pg_restore версии 16. Поднимает временную локальную БД в /private/tmp через Unix socket, восстанавливает данные, сверяет строки, останавливает БД и удаляет временный каталог. Не запускать от root. |
| [test-verify-export.py](test-verify-export.py) | Восемь локальных тестов, включая защиту от повреждения и опасного SQL. | Только временные синтетические файлы; сетевые и внешние команды в тестах экспортёров заменены mock-объектами. |

PostgreSQL-пути по умолчанию: `/opt/homebrew/opt/libpq@16/bin` для экспорта и
`/opt/homebrew/opt/postgresql@16/bin` для восстановления. Их можно заменить
аргументами `--client-bin` и `--server-bin`; каталог `/private/tmp` в проверке
восстановления пока привязан к macOS. Наличие `yc` не подтверждает действительность
профиля, прав или доступность старых ресурсов.

## Границы безопасности

- Экспорт БД запрещает ID исходного production-кластера, требует имя
  `ncfg-db-rescue-*`, RUNNING, PostgreSQL 16 и один ожидаемый host. Это проверки
  конфигурации, а не замена согласованию конкретного recovery-клона.
- Подключение использует TLS verify-full, в том числе через локальный туннель,
  и read-only транзакции. У клона не должно быть других писателей: счётчики строк
  и pg_dump снимаются последовательно, не в одном общем снимке транзакции.
- IAM и пароль не сохраняются в исходниках или отчётах. Пароль передаётся pg_dump
  через окружение процесса; локальные привилегированные процессы могут его видеть.
  Registry-токен не пересылается при redirect, а авторизованные запросы страниц
  и Lockbox не следуют перенаправлениям. Сырые ошибки этих операций подавляются.
- Использовать отдельный закрытый каталог назначения без чужих файлов и symlink.
  umask 077 защищает вновь создаваемые файлы, но не исправляет права существующих.
  Экспорт media/pages может перезаписать свои файлы; OCI поддерживает докачку.
  Экспорт БД отказывается перезаписывать dump и сопроводительные файлы счётчиков.
- Дампы, приватные образы и выгрузки могут содержать персональные данные и секреты.
  Эти утилиты не шифруют результат: хранить его закрыто, не добавлять в Git.
- Проверка SHA-256 подтверждает целостность, а не происхождение или безопасность
  дампа. Восстанавливать только доверенные собственные выгрузки. Временная БД
  без TCP и роль strapi без superuser не являются песочницей ОС.
- Проверка восстановления принимает только фиксированный запрос подсчёта строк,
  совпадающий с экспортёром; произвольный SQL из row-counts.sql отклоняется до
  запуска PostgreSQL. Сверка количества строк не подтверждает равенство всех значений.
- Отчёт verify-export проверяет перечисленные в манифестах объекты; он не является
  аудитом происхождения манифестов или отсутствия лишних файлов в каталоге.

## Безопасные локальные проверки перед коммитом

Из корня репозитория:

```sh
PYTHONDONTWRITEBYTECODE=1 python3 infra/cloudru/test-verify-export.py
python3 -B infra/cloudru/export-images.py --help
python3 -B infra/cloudru/export-media.py --help
python3 -B infra/cloudru/export-pages.py --help
python3 -B infra/cloudru/export-postgres.py --help
python3 -B infra/cloudru/verify-export.py --help
python3 -B infra/cloudru/verify-postgres.py --help
```
