# AGENTS.md

## Локальная разработка

- Обычный запрос «подними сайт / локальную разработку с production Strapi»
  означает `npm run dev` из корня. Этот профиль уже включает Next.js frontend
  и `app/api` backend; локальные PostgreSQL, MinIO и Strapi ему не нужны.
- `npm run dev:cms` используй только для разработки CMS, `npm run dev:full` —
  когда явно нужен полностью локальный стек.
- При сбое сначала запускай `npm run dev:doctor`. `npm run dev:verify` только
  проверяет readiness уже работающих сервисов.
- Не запускай вручную `npm ci`, Docker/Colima, локальный CMS, синхронизацию БД,
  build, lint или browser QA как часть обычного старта: launcher сам выполняет
  необходимый preflight и readiness.
- Не получай production write-token, не включай реальные почтовые/CRM-интеграции
  и не smoke-тестируй submit endpoints в обычной локальной разработке.
- Не сохраняй Lockbox payload в `.env*` или другие файлы и не выводи секреты в лог.
- Не переключай ветку и не выполняй `git pull` автоматически. При явном запросе
  запуска с `main` сначала безопасно проверь ветку и dirty worktree.
- Строка `READY` означает успешное развёртывание; не повторяй расширенный QA без
  отдельной причины. Канонический runbook: `DEVELOPMENT.md`.

## Frontend/UI

- Перед любыми frontend/UI-изменениями загружай repo-local skill `$impeccable`.
- Используй Impeccable как базовый слой качества. `apps/web/PRODUCT.md`,
  `apps/web/DESIGN.md`, существующие токены, компоненты и ближайшая реализация
  являются авторитетным проектным слоем и имеют приоритет в визуальных решениях.
- Не редактируй `.agents/skills/impeccable`: каталог управляется официальным установщиком.
- После UI-изменений учитывай замечания project hook; намеренные исключения оформляй узко.

## Эксперименты и лаборатории

- `/experiments` — постоянная внутренняя разводящая страница для всех UI-экспериментов,
  прототипов и лабораторий. Каждый новый эксперимент создавай отдельным маршрутом вне
  публичного `(site)` layout и регистрируй в `EXPERIMENTS` внутри
  `apps/web/app/experiments/page.tsx`.
- `/experiments` и каждый экспериментальный маршрут должны иметь `noindex, nofollow`;
  не добавляй их в публичную навигацию, sitemap или production-аналитику.
- После принятия или закрытия эксперимента удаляй его из реестра и убирай временные
  варианты из production-кода. Саму страницу `/experiments` не удаляй, даже если список пуст.

## Bootstrap (обязательно)
Перед любыми изменениями:
1) открой и прочитай если есть `CLAUDE.md` и `.claude/CLAUDE.md`
2) если есть — прочитай все файлы `.claude/rules/*.md`

Если инструкции здесь конфликтуют с `CLAUDE.md` — следуй `CLAUDE.md`.

После прочтения кратко подтверди, что применяешь эти правила, и только потом приступай к задаче.
